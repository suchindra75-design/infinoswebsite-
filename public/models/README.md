# 3D Assets — Real INFINOS Product Model Contract

Place the real INFINOS smart thermal bag/container model here. Everything below is a
**technical requirement for the asset pipeline** — no component names, dimensions, or
specifications are claimed as fact. Component names shown are an **example convention only**;
real names are assigned after the INFINOS CAD/product model is provided.

## Pipeline (how the real model plugs in)

1. Export the GLB per this contract and place it at `public/models/<product-slug>.glb`.
2. Open `src/content/products.ts` and set `PRODUCT.model.source` to `"/models/<product-slug>.glb"`.
   That single switch (`src/content/assetConfig.ts`) moves the scene from placeholder geometry to
   the real model — no scene architecture changes.
3. Rename the model's layer nodes to match `components[].nodeName` (below), and tune
   `components[].explode` (direction/distance/rotation) to the real geometry.
4. Update `PRODUCT.model.display.anchor` to the real display position (or keep it and verify).
5. Replace placeholder copy/specifications in `content/` — real values only.

## File format

- **GLB** (binary glTF 2.0). `.gltf` + separate buffers accepted but GLB strongly preferred.

## Coordinate system, scale, origin

- **Y-up, right-handed** (glTF standard). Fix orientation in the DCC before export.
- **Real-world scale in meters.** The scene normalizes automatically to
  `PRODUCT.model.targetHeightMeters` (a scene-fit parameter, currently a placeholder value —
  confirm with real product dimensions), but correct source scale is still required.
- **Origin of the assembled product:** base center — the product sits on the ground plane
  `y = 0`, centered at `x = 0, z = 0`.

## Camera assumptions

- Perspective, FOV 35°, near 0.1 / far 60.
- Framing presets live in `src/components/product/CameraController.tsx` (one per product state).
  Model must fit a front-elevated exploded framing at distance ~8m and a close-up framing at
  ~1.9m (telemetry/display shot). Tune presets after the real model arrives if needed.

## Geometry budget

- Desktop: **< 100k triangles** total. Mobile: **< 50k triangles** preferred.
- CAD-derived geometry must be decimated for web; keep hard edges/silhouette quality.

## Textures & PBR

- **PBR metal-rough** workflow (glTF standard: `baseColorFactor/Texture`,
  `metallicFactor`, `roughnessFactor`, `normalTexture`, optional `emissive`).
- Texture resolution: **max 2048×2048**, 1024×1024 preferred; mobile ideally one shared atlas.
- **Compression: KTX2 / Basis Universal** strongly preferred (BasisU); PNG/JPEG accepted as
  fallback. Enable **meshopt or Draco** geometry compression (decoder is available via drei).
- Keep material count low (ideally < 8). Shared materials reduce draw calls.

## Hierarchy & naming conventions

- One **group (empty node) per physical layer**, as a **direct child of the model root**, with
  **identity transform** — the exploded-view system moves these groups.
- Node names must match `components[].nodeName` in `src/content/products.ts`.
  Current example convention (PLACEHOLDER ONLY — real names assigned with the CAD model):

  ```
  INFINOS_Product                 (model root)
  INFINOS_Lid                     (lid / display module)
  INFINOS_OuterShell              (outer shell)
  INFINOS_Insulation              (insulation / thermal barrier)
  INFINOS_PayloadCompartment      (payload compartment)
  INFINOS_SensorSystem            (sensor system)
  INFINOS_ThermalSystem           (thermal system — cooling/heating)
  INFINOS_Electronics             (electronics / control system)
  ```

- **Component pivots:** each layer group's pivot at its own resting position in the assembled
  product, identity rotation. The loader captures each node's rest transform and registers it;
  the exploded-view controller offsets from there.
- Matched nodes are re-parented by the loader into per-component wrappers (world transform
  preserved), so nesting errors are tolerated — but author the hierarchy flat as specified.

## Animation

- **None required.** The website animates layers itself (scroll-driven exploded view, state
  transitions). If the CAD model includes a closed/open clip, it may be used later via the
  reserved `openOffset` field on `components[]` — not required for the current build.

## Size limits & delivery checklist

- **Maximum recommended file size: 5 MB** (target < 3 MB desktop; < 1.5 MB mobile variant if a
  separate mobile asset is produced).
- The model is lazy-loaded: it is fetched only when the product experience requires it
  (first scroll into the narrative), with loading progress, error fallback to the placeholder,
  and registry cleanup on unmount.
- Checklist: ☐ Y-up ☐ meters ☐ origin base-center ☐ layer groups as root children ☐
  identity pivots ☐ names match `nodeName` ☐ ≤ 100k tris ☐ KTX2/meshopt ☐ ≤ 5 MB

## Mobile considerations

- Reduced DPR (clamped 1–1.5), reduced contact-shadow resolution, simplified lighting, reduced
  exploded distances (×0.55) are handled automatically by the scene — the asset should simply
  respect the triangle/texture budgets above. A separate lighter mobile GLB is optional; if
  provided, extend `assetConfig.ts` with a mobile path.
